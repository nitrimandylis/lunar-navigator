# Project submission page guide

Reviewed: 14 November 2026. Primary source: current NASA Project Submission Guide [N02](sources.md#n02).
Source locations refer to printed pages in Nick's uploaded 15-page PDF; [sources.md](sources.md) contains exact URLs and records.

## Purpose and priority

The full project page deserves as much preparation as the demo: NASA states that the majority of evaluation is based on the project submission. Presentation also includes the full project. [N02 p. 6; N01 p. 7]

Use current NASA instructions first. The suggestions below about structure, evidence and avoiding repetition are **our writing recommendations**, not extra required fields. We have not inspected the live team's form; do not invent field character limits or assume a guide heading proves that a field is mandatory. Complete the actual form's required fields.

## Recommended detailed-description structure

This is our proposed writing structure. It is not a NASA-mandated word count or template.

1. **Problem and users.** Explain the site/date decision and the two audience needs in plain language.
2. **Demonstrated solution.** Describe what the current website lets a user do, in task order.
3. **One reproducible example.** Record selected sites, coordinates, date/window and time convention; show the values and a supported interpretation.
4. **Data and method.** Name actual NASA sources, transformations, definitions and assumptions. Explain how results reach the interface in terms a reader can follow.
5. **Validation and usability.** Report checks actually performed, observed outcomes and meaningful user feedback, with evidence.
6. **Creativity and benefit.** Explain the particular workflow improvement and why it matters to the intended users.
7. **Limitations and current status.** Distinguish verified behavior, unvalidated behavior, mockups and future plans.
8. **Tools and next steps.** Describe relevant tools and the most valuable remaining work. Keep attribution and SI details consistent with their dedicated fields.

Do not invent performance, user testing, endorsement, adoption, mission readiness or a completed validation process. A brief accurate statement is stronger than an elaborate unsupported one.

## Evidence to request from teammates

Ask for facts and evidence, not code changes. Nick's role remains presentation, research and submission.

| Needed information | What to record | Confirm with |
| --- | --- | --- |
| Working features | What works now, what is incomplete, what the demo can show | trim |
| NASA data | Exact products/URLs, versions, retrieval dates and actual usage | gio |
| Site inputs | Site names, coordinate source/convention and observer height | gio |
| Dates and coverage | Time system, supported range, sample interval, missing values | gio |
| Visibility meaning | Geometric vs terrain-aware horizon; Sun/Earth definitions and event-time precision | gio |
| Power/comms scope | Which quantities are estimates, what is outside the model | gio |
| Validation | Reference case, comparison method, result and limitations | gio |
| Reproducible comparison | Supported sites and common window, values and evidence | gio + trim |
| Public links | Final app, repository/supporting materials, stable demo link | trim + Nick |
| Assets and SI | Actual sources, rights, tools, generated elements and indicators | whole team |

Candidate sources such as Horizons, LOLA, Moon Trek and QuickMap must not be listed as implemented data feeds until confirmed. Background research, textures and analytical inputs have different roles; state them correctly.

## Submission workflow

1. Go to profile -> My Team -> Project -> Edit. The Project tab is available during the event. [N02 p. 3]
2. Coordinate a single person entering the final text. Use the edit lock and save frequently; another member can override the lock. [N02 pp. 3-4]
3. Fill the required fields and attach public external links. Supporting JPG/PNG/GIF images can be uploaded, up to 10 MB; documents/videos cannot be directly uploaded. [N02 p. 4]
4. Check all claims against the final product, source credits, SI indicators and permitted under-18 credits.
5. Test every link in a private browser. A new website may optionally receive FortiGuard classification; this is recommended, not mandatory. [N02 pp. 4-5]
6. Read the terms and original-work declaration and only confirm them truthfully.
7. Click **Submit for Judging** before 15 November 2026, 11:59 p.m., Athens Local Event time. Observe the confirmation banner. [N02 p. 12]
8. If editing afterward, save and resubmit before the deadline; confirm the final published state. The last saved submission is what judges review. A private draft is not a replacement submission. [N02 pp. 3, 12; N03 1:34-2:02]

Allow a team-chosen buffer for access/export problems. That buffer is our planning advice, not NASA's deadline. Do not rely on late edits or exceptions; the video says none are allowed. [N03 8:38-8:54]

- [ ] SI response is accurate and all required content indicators are present.

- [ ] No placeholder results or unsupported scientific/performance claims.
- [ ] Required declarations checked truthfully.
- [ ] Submit for Judging completed, banner observed, final published version checked.

## Avoid misleading submission assumptions

- The deck alone is not the complete submission.
- Winning a local award does not automatically produce a Global Nominee.
- A GitHub repository is not the only permitted final-project host [N08](sources.md#n08).
- Having a public website does not prove the NASA project form was submitted.
- There is no verified requirement here for a 1,000-word description, exactly seven slides, a 3-minute pitch or an additional official video.
- Do not claim all five criteria have equal percentage weights; current sources specify 1-5 evaluation per criterion without percentages.
- The SI form answer being hidden from judges does not remove disclosure/indicator obligations.
- Do not include identifiable under-18 audio/video/images merely because it appears in an adult team's past submission.

## After submission

Certificates become available through Profile -> Participant Information -> 2026 -> Download Participant Certificate. The guide specifies a PDF download and suggests using a desktop/laptop. Profile Full Name controls the certificate name and can be changed later. [N02 p. 14]

Announcement dates and award progression are in [nasa-rules-and-rubric.md](nasa-rules-and-rubric.md). Keep the final submission facts and evidence available to the team.
